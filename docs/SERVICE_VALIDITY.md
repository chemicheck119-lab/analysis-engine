# 케미체크119 서비스 타당성 및 AI 적용 판단

기준일: 2026-07-31
결론: **핵심 문제는 실제로 존재하지만, “화학사고 챗봇”이 아니라
“출동 중 확인해야 할 물질과 충돌 근거를 먼저 정리하는 안전 보조도구”로 정의해야
타당합니다.**

## 1. 쉬운 결론

소방대원이 필요한 것은 AI가 그럴듯한 답을 길게 말하는 기능이 아닙니다.

1. 신고 내용에서 물질 후보를 빠르게 찾고,
2. 해당 업체의 과거 취급 이력을 “후보”로 보여주고,
3. 현장에서 라벨·MSDS 등으로 두 물질을 확인하면,
4. 공개 CAMEO 규칙으로 혼합 위험을 검토하고,
5. 판단 근거와 추가 확인사항을 짧은 카드로 보여주는 기능이 필요합니다.

이 흐름은 [NIST의 응급대응 인지 보조 연구](https://www.nist.gov/ctl/pscr/cognitive-assistant-systems-emergency-response)가
지적한 구조·비구조 정보의 수동 취합 부담을 줄이는 방향과 일치합니다. NIST는
응급대응자가 중요도와 신뢰도가 다른 많은 정보를 빠르게 처리해야 하고, 수동 취합에는
큰 인지 부담이 든다고 설명합니다.

현실 사례도 있습니다. 미국 CSB의
[Blues City Brewery 사고 보고서](https://www.csb.gov/assets/1/6/incident_reports_volume_3_2025-07-22.pdf)
에는 작업자가 산성 용액을 표백제 용액 탱크에 잘못 이송해 염소가스가 발생했고,
10명이 병원으로 이송된 사고가 기록돼 있습니다. 즉 “시설 안에 다른 물질이 무엇인지,
두 물질이 만나면 무엇이 생기는지”를 빨리 확인하는 문제는 실제 문제입니다.

## 2. 반드시 살릴 기능

| 기능 | 이유 | 화면 표시 |
|---|---|---|
| 신고문 물질 후보 추출 | 구어체 신고를 검색 가능한 표현으로 바꿈 | 후보명·CAS·확인 필요 |
| 물질검색/RAG | 이름이 부정확해도 공식 문서 후보를 찾음 | 공식 근거 카드와 출처 |
| ICIS·PRTR 업체 이력 | 현장에 있을 가능성이 있는 물질의 탐색 범위를 줄임 | `과거 이력`, `현재 재고 미확인` |
| 두 물질 현장 확인 gate | 잘못 찾은 후보로 충돌 판정하는 것을 막음 | 사고물질·시설물질 확인 상태 |
| CAMEO 결정 규칙 | LLM 추측 없이 재현 가능한 충돌 검토 | 등급·반응·규칙 버전·URL |
| 전체 대응기록 저장 | 사후 감사와 인수인계에 필요 | 대화·확인·판정·근거를 한 기록으로 저장 |

[NOAA CAMEO Chemicals](https://cameochemicals.noaa.gov/about)는 응급대응자용 유해물질
데이터시트, 누출·소방 대응 정보와 물질 혼합 시 잠재 위험 예측 기능을 제공합니다.
따라서 CAMEO를 결정론적 규칙 근거로 사용하는 방향은 서비스 목적과 맞습니다.

## 3. 바꾸거나 축소할 기능

| 기존 기획 | 판단 | 권장 변경 |
|---|---|---|
| 챗봇 중심 대응충돌검토 | 축소 | 대화는 보조로 두고 상태 카드·확인 버튼을 우선 |
| 신고문에서 시설·주소까지 모두 AI 추출 | 초기 필수 아님 | 주소·시설은 상황실/BE의 구조화 값 우선, 원문 파싱은 보조 |
| 성상만으로 물질 확정 | 위험 | 복수 후보만 반환하고 라벨·MSDS 확인 전 확정 금지 |
| 업체 이력을 시설 보유물질로 표시 | 부정확 | `과거 취급 후보`, `현장 확인 필요`로 고정 |
| 위험도를 퍼센트로 표시 | 근거 없음 | CAMEO 원본 서수 등급과 `is_probability=false` 사용 |
| 미확인 상태에서 낮음/중간/높음 표시 | 위험 | 두 CAS 확인 전에는 위험도 영역 자체를 숨김 |
| 기록저장과 화면 초기화 동시 실행 | 데이터 유실 위험 | 저장 성공 확인 뒤 사용자가 별도로 새 사고 시작 |
| 지도에 고정 800m 확산반경 | 근거 부족 | ALOHA/ERG 등 입력·계산 근거가 없으면 “예시” 제거 |

특히 지도 확산반경은 풍향·풍속만으로 정확하게 계산할 수 없습니다. 방출량, 물질 상태,
기상 안정도와 지형 등 필요한 입력과 검증된 모델이 연결되기 전에는 AI 예측값처럼
표시하면 안 됩니다.

## 4. 빼거나 뒤로 미룰 기능

- 화학배관 피해 예측: 현재 서비스 핵심 문제와 데이터가 맞지 않습니다.
- LLM이 직접 만드는 충돌 위험등급·대응 절차: 안전 근거와 재현성이 없습니다.
- 정답이 없는 생성형 파인튜닝: 신고문 QLoRA용 검수 전사·개체 라벨은 현재 0건입니다.
- 사고 표현 Resolver 적응학습은 별도입니다. 공개 CAS 정답을 이용해 완료했지만 처음 보는
  표현 성능은 개선되지 않아 범용 언어 이해로 주장하지 않습니다.
- “최신 기술”을 위한 무조건적인 GraphRAG·Agent·Dense 검색: 기준선보다 좋아졌다는
  동일 평가셋 결과가 나온 뒤에만 채택합니다.
- 전국 서비스 주장: 업체 이력과 공개 규칙 지원 범위가 아직 제한적입니다.

## 5. 공모전에서의 참신성

발표 명칭은 다음처럼 정리합니다.

> **Evidence-Gated Hybrid Incident Copilot**
> 사전·검색 모델이 후보와 공식 근거를 찾고, 현장 확인 gate와 결정론 규칙이 후보의
> 오판 승격을 막는 화학사고 의사결정 지원 AI

참신성은 거대한 생성형 모델이 아니라 다음 결합에 있습니다.

- sparse retrieval(BM25·TF-IDF)로 CPU 배포 가능
- 모호하면 답하지 않는 selective abstention
- 사람이 확인한 CAS 두 개만 규칙 입력으로 허용
- CAMEO 규칙과 LLM 역할 분리
- 데이터·모델·규칙·근거 URL provenance
- LLM 장애 시에도 핵심 기능 유지

[NIST의 Smart Firefighting 연구](https://www.nist.gov/programs-projects/artificial-intelligence-enabled-smart-firefighting)도
실제 응급대응 AI를 고충실도 데이터 수집, 전처리, 모델 개발·검증, 배포·시험의 순서로
진행합니다. 케미체크119 역시 모델 이름보다 검증 가능한 데이터와 배포 시험을 우선합니다.

## 6. 이번에 추가한 E2E 검증

기존 숫자의 출처는 다음과 같습니다.

- 물질 식별 21건: `resolver_regression_queries.csv`
- 근거 검색 10건: `retrieval_regression_queries.csv`
- 신고문 파서 6건: `incident_parser_seed.jsonl`의 DRAFT 시드이며 성능 평가가 아님

이 숫자는 각 모듈의 작은 회귀검사일 뿐 전체 서비스를 검증하지 못했습니다. 그래서
`evaluate-e2e`를 추가했습니다.

```bash
chemiguard119 evaluate-e2e \
  --evaluation-profile INTERNAL_REGRESSION \
  --json
```

2026-07-31 실제 artifact 실행 결과:

```text
시나리오 8/8 통과
미확인 상태 Rule 실행 0건
미확인 위험등급 노출 0건
기권 필요 시나리오 7/7 통과
평균 86.610ms / p95 112.537ms
claim_scope=INTERNAL_REGRESSION_ONLY
```

8건은 확인 상태, 모호한 별칭, 부분 문자열, 잘못된 CAS, 지원되지 않는 물질쌍을 검사합니다.
이 결과는 “설계한 안전 상태 전이가 현재 코드에서 작동한다”는 뜻일 뿐 정확도 100%나
상용 준비 완료를 뜻하지 않습니다.

## 7. 상용화 판단

| 단계 | 현재 판단 | 이유 |
|---|---|---|
| 공모전 데모 | 가능 | 핵심 흐름·API·안전 gate·E2E 회귀 존재 |
| 제한된 내부 파일럿 | 조건부 불가 | 독립 검수 E2E 200건, parser 400건 등이 아직 없음 |
| 현장 운영 | 불가 | 실제 소방대원 사용성·현장 데이터·스테이징 장애시험 없음 |
| 전국 상용 서비스 | 불가 | 업체·근거·CAMEO 지원 범위와 운영 책임체계 부족 |

다음 우선순위는 모델을 더 붙이는 것이 아니라 다음 세 가지입니다.

1. FE·BE가 물질 후보 → 현장 확인 → 통합 분석 → 기록 저장 순서를 실제로 연결
2. 공모전에는 [공식근거 보증 기준](COMPETITION_ASSURANCE.md)을 적용하고, 사람 검수 E2E는
   실제 파일럿을 시작할 때 50건에서 200건 이상으로 확장
3. 오류·미등록·근거 없음·네트워크 장애를 포함한 FE·BE 통합 환경 시험

파인튜닝은 신고문 locked test에서 규칙 기준선의 실패가 충분히 모인 뒤, 경량 NER가
정확도와 지연시간을 실제로 개선할 때만 다시 검토합니다.
