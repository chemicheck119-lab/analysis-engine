# 회의에서 전달할 Resolver 고도화 결과

2026-09-11 · 이번 범위: 물질 후보 검색 실험과 평가 코드. 원격 CI 검증 진행 중.
전체 서비스·현장 적용 완료 보고가 아니다. 자세한 근거는 [평가 보고서](RESOLVER_DOMAIN_RESULTS.md).

## 1분 설명

> 이번에는 물질명을 못 찾는 문제를 세 부분으로 나눠 실험했습니다.
> 첫째는 검색 목록에 공식 이름이 빠진 문제, 둘째는 후보는 찾았지만 순서가 틀린 문제,
> 셋째는 서로 다르게 쓰인 같은 물질명을 모델이 연결하지 못하는 문제입니다.
> 공식 이름을 보강하고, 후보 20개를 재정렬하고, 검색 벡터를 보정하는 작은 모델을 각각 시험했습니다.
> 핵심 학습 결과는 학습에 쓰지 않은 CAS의 공식 명칭 264건에서, 정답을 상위 3개 후보 안에
> 넣은 건수가 106건에서 145건으로 증가한 것입니다. 다만 아직 119건을 놓칩니다.
> 따라서 운영 모델은 교체하지 않고, 다음 단계에서 세 방법의 결합과 손실 사례를 검증하기로 했습니다.
> 후보는 사람이 확인하고, 두 CAS를 각각 확인한 뒤에만 조합 규칙을 실행하는 원칙도 유지합니다.

## 회의 화면에 보여줄 숫자는 이 표 하나

Top-3는 **상위 후보 세 개 안에 공식 정답 CAS가 있었는지**다. CAS를 자동 확정한 정확도가 아니다.

| 서로 별개인 실험 | 평가 자료 | 기준 → 실험 | 반드시 같이 전달할 한계 |
|---|---|---|---|
| 공식 이름 1,626개 보강 | 이미 관찰된 2020 미관측 표현 60건 | Top-3 24→43건 | 평가 표현 19개가 새 자료에 직접 있음. 일반화 개선으로 주장하지 않음 |
| 기존 Top-20 후보 재정렬 | 위와 같은 60건·기존 후보 목록 | Top-3 24→31건 | 8건 개선·1건 손실. 후보 목록 밖의 정답은 구할 수 없음 |
| 검색 보정층 학습 | CAS 단위로 학습/개발/평가를 분리한 공식 명칭 264건 | Top-3 106→145건, **40.15%→54.92%** | 50건 개선·11건 손실. 현장 음성 평가·외부 전문가 검수가 아님 |

세 행의 숫자는 더하거나 평균 내지 않는다. 앞 실험에 다음 실험을 누적한 결과도 아니다.
264건은 울산 419건 Resolver 평가나 전국 442건 Parser 평가와 다른 benchmark다.

## 왜 이 방향인가

- **자료:** 빠져 있던 정답 CAS 12개는 모두 공식 파일에서 찾았다. 데이터 확보 경로가 있다는
  증거이지, 새 CAS를 안전하게 자동 식별할 수 있다는 증거는 아니다. 아직 활성화하지 않았다.
- **모델:** BGE-M3 전체를 학습한 것이 아니다. 같은 CAS 이름을 가깝게 만드는
  contrastive learning으로 65,536개 파라미터의 작은 보정층을 학습했다.
- **학습 판단:** 20 epoch까지 돌렸지만 dev는 5 epoch에서 가장 좋았다. 오래 학습하면
  좋아진다는 전제를 버리고, 사전에 정한 dev 선택 규칙을 적용했다.
- **서비스:** 더 나은 후보를 짧게 보여줘 사람이 확인하도록 돕는 방향이다.
  이번 실험에서 실제 소방대원의 확인 시간 단축을 측정한 것은 아니다.

## 이번에 끝낸 것과 아직 아닌 것

| 상태 | 내용 |
|---|---|
| 부분 구현 또는 개발용 데모 | 세 실험·실제 artifact 평가·누수 검사·재현 문서·로컬 718개 테스트, 공개 CI 진행 중 |
| 부분 구현 또는 개발용 데모 | 재정렬/보정층은 조건부 후속 후보. 현재 API는 Sparse 유지 |
| 설계 완료·구현 전 | 공식 이름 보강 + 보정층 + 재정렬 결합 평가, 신규 CAS 노출 정책 평가 |
| 검증되지 않은 가설 | 현장 신고/무전 정확도, 실제 사용자 확인 시간 단축, 현장 안전성 |

코드·집계만 공개하고 원본·별칭 행·평가 질의·벡터·가중치는 비공개다.
추가 개발 서버 비용은 **0원**이고, 기존 GCP 누적 비용을 새로 확인한 것은 아니다.
이번 변경은 Model API의 응답 계약·Front·Backend·GCP를 바꾸지 않는다.

## 회의에서 결정받을 다음 세 가지

1. **현재 서비스 기본값은 Sparse 유지.** 새 모델은 자동 교체하지 않고 별도 실험 후보로 관리한다.
2. **다음 모델링 목표는 결합 효과와 실패 조건 검증.** 개발셋에서 결합 구성을 선택하고,
   이미 결과를 본 264건·2020 자료를 다시 비공개 test처럼 사용하지 않는다.
3. **제품 연결의 수용 기준을 합의.** 후보가 틀렸을 때 보류/추가 확인을 할 수 있는지,
   후보·확정의 화면 구분과 두 CAS 확인 조건을 실제 연동에서도 유지하는지 확인한다.
   속도와 사용자 이득은 API 연결 뒤 별도로 측정한다.

## 예상 질문에 짧게 답하기

**“그래서 정확도 71.67%라는 거죠?”**

아닙니다. 기존 60개 표현을 새 공식 이름으로 보강한 사후 검색 결과입니다.
모델 학습 효과는 별도 CAS 분리 264건에서 Top-3 40.15%→54.92%로 설명해야 합니다.

**“54.92%면 바로 써도 되나요?”**

아직 아닙니다. 정답 없는 사례와 기존 정답 손실이 있습니다. 후보 검색 개선의 증거만 확보했고,
실제 현장 사용 승인을 받은 것이 아닙니다. 사람 확인과 보류가 계속 필요합니다.

**“이게 음성 모델 성과인가요?”**

아닙니다. 이번은 물질 이름 텍스트를 CAS 후보에 연결하는 Resolver 실험입니다.
STT·Parser·Retriever·행동 카드 API의 성능과 따로 설명해야 합니다.

**“개발을 완료했다는 뜻은?”**

이번 실험 코드·재현 가능한 결과·공개 PR·CI 검증 범위의 완료를 뜻합니다.
main 병합, 운영 모델 교체, 실제 소방 적용까지 완료했다는 뜻은 아닙니다.
