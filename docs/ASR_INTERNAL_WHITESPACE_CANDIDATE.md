# ASR 내부 공백 후보 실험

## 결론

사실 상태는 **부분 구현 또는 개발용 데모**입니다. 긴 한글 물질명의 문자 사이 공백을
허용하는 후보 규칙은 관측된 합성 음성 실패를 로컬에서 회복했지만, 전국 공식 사고문
442건 비교에서 정확 표면형 Recall이 하락했습니다. 따라서 현재 코드는 검토 후보이며
런타임 기본값으로 채택하거나 배포하지 않습니다.

## 왜 시작했나

2026-09-09 Cloud Run 합성 음성 E2E 두 번은 모두 64개 검사 중 61개를 통과했습니다.
Speech API는 첫 물질명을 내부 공백이 추가된 형태로 전사했고, Parser는 긴 물질명을 놓친 뒤
그 안의 짧은 물질만 추출했습니다. 그 결과 사고물질 후보가 기대 CAS와 다른 CAS가 됐습니다.
다만 두 CAS 확인 전 Rule 실행과 위험 표시는 모두 차단됐습니다.

컨테이너 layer를 감사한 결과 Cloud Run과 로컬은 다음 조건이 같았습니다.

- faster-whisper 1.2.1
- CTranslate2 4.8.2
- `Systran/faster-whisper-small` revision `536b066...`
- `model.bin` SHA-256 `3e305921...`
- CPU int8, hotword 미사용

따라서 현재 한 건의 관측에서는 가중치 차이가 아니라 ARM64와 x86_64의 int8 디코딩 표기
차이로 분류했습니다. 한 건뿐이므로 아키텍처 일반 현상으로 확대 해석하지 않습니다.

## 후보 규칙과 안전 경계

후보 코드는 6글자 이상인 한글 별칭에 한해서 문자 사이 공백을 허용합니다. 전사문이나
원문 surface를 교정된 문자열로 덮어쓰지 않습니다. 찾아낸 결과도 CAS 확정이 아니라
대원 확인이 필요한 후보이며 `rule_input_eligible=false`를 유지합니다.

## 비교 결과

동일한 공개 원천 442건과 동일 Resolver artifact에서 기존 `main`과 후보 코드를 비교했습니다.
이는 기존 공개 수치 81.50%를 새 수치로 대체하는 평가가 아닙니다. 기존 공개 수치는 당시의
다른 Resolver artifact로 측정됐고, 이번 비교는 현재 staging artifact에서 코드 변화만
분리한 회귀 검사입니다.

## 결정

**조건부 검토, 런타임 채택 보류**입니다. 합성 실패 1건을 고쳤다는 이유만으로 정확 표면형
하락을 무시할 수 없습니다. 다음 단계는 잠금 구간 실패 원문을 들여다보는 것이 아니라,
2014~2020 개발 구간에서 후보 규칙 때문에 달라진 span만 별도 검수하는 것입니다. 사람이
오탐 여부를 결정하기 전에는 Cloud Run 재배포와 성공 주장 모두 금지합니다.

## 개발 구간 인간 검수 Gate

2014~2020 공식 사고문 개발 구간 584건을 같은 코드에서 기준선 옵션과 후보 옵션으로 다시
파싱했습니다. 변경된 30건만 비공개 검수 큐로 만들었고, 사람 판단은 한 건도 자동 입력하지
않았습니다.

| 항목 | 결과 |
|---|---:|
| 개발 사례 | 584건 |
| Parser 결과가 달라진 사례 | 30건 |
| 공식 라벨 exact 일치 개선 사례 | 4건 |
| 공식 라벨 exact 일치 악화 사례 | 16건 |
| 공식 라벨 containment 개선 사례 | 2건 |
| 공식 라벨 containment 악화 사례 | 0건 |
| 기준선·후보의 미확인 Rule 입력 승인 | 각각 0건 |
| 인간 검수 완료 | 0/30건 |

exact 일치 악화 16건을 곧바로 오탐 16건으로 해석할 수는 없습니다. 후보가 더 긴 실제 물질
span을 잡아도 기존 공식 라벨과 문자열이 완전히 같지 않으면 exact 지표는 내려갈 수 있기
때문입니다. 반대로 containment 유지만으로 새 span이 모두 옳다고 볼 수도 없습니다. 따라서
검수자는 각 사례에서 “새로 선택된 span이 실제 물질 언급인가?”를 `ACCEPT`, `REJECT`,
`AMBIGUOUS` 중 하나로 판단해야 합니다.
